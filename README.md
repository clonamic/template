# template

작업명세서, 개발명세서, 보고서 형식의 원본 모음이다. 형식은 여기서만 고친다.

## 문서와 순서

| 문서 | 하는 일 | 끝 문장 |
| --- | --- | --- |
| [작업명세서](작업명세서.md) | 무엇을 할지와 완료 기준을 고정한다 | 승인 대기 — 작업명세서 |
| [개발명세서](개발명세서.md) | 무엇을 어떻게 바꾸고 어떻게 증명할지 고정한다 | 승인 대기 — 개발명세서 |
| [보고서](보고서.md) | 결과를 증거와 함께 한 번 알린다 | 없음 |

흐름: 작업명세서 → 승인 → 개발명세서 → 승인 → 실행 → 보고서.

- 읽기와 설계만인 작업은 작업명세서 승인 뒤 바로 하고 개발명세서를 쓰지 않는다.
- 사용자가 대상과 변경을 정확히 정한 아주 작은 변경은 개발명세서 한 줄 형식 하나로 끝낸다.
- 질문, 설명, 조회, 상태 확인에는 어떤 문서도 쓰지 않는다.

## 번호

같은 번호가 세 문서를 관통한다.

| 작업명세서 | 개발명세서 | 보고서 |
| --- | --- | --- |
| 요구1 (산출1·제외1) | 변경1 (복구1은 프로젝트 밖일 때만) | |
| 완료1 | 검증1 | 결과1 |

번호가 어긋나면 `변경3 [요구1]`, `결과2 [완료2]`처럼 대응을 적는다.

## 공통 규칙

- 세 문서 모두 채팅에만 쓰고 파일로 만들지 않는다.
- 이름은 고정이다. 버전, 단계 번호, 다른 이름을 붙이지 않는다.
- 승인 대기 중인 명세서는 늘 하나다.
